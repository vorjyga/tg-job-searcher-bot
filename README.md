# Telegram jobs searcher

Telegram-бот, который ищет ключевые слова в группах и каналах, доступных подключённому
Telegram-аккаунту, и отправляет результаты каждому настроившему поиск
пользователю отдельно.

Реализованы этапы 1–6: каркас приложения, конфигурация,
PostgreSQL-схема, Alembic-миграции, JSON-логи, защита от одновременного
запуска, авторизация Telegram-аккаунта, личный интерфейс бота, мониторинг
новых сообщений и фоновое сканирование истории.

## Требования

- Python 3.12–3.14;
- PostgreSQL 15 или новее;
- отдельная база и пользователь PostgreSQL для приложения.

## Установка и проверка подключения

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
cp .env.example .env
```

Заполните `DATABASE_URL` в `.env` и экспортируйте переменные в окружение:

```bash
set -a
. ./.env
set +a
alembic upgrade head
tg-jobs-searcher --check
```

Для Supabase можно вставить строку подключения из Dashboard → Connect, заменив
префикс `postgresql://` на `postgresql+asyncpg://`. Стандартный параметр
`sslmode=require` поддерживается приложением. Прямой адрес вида
`db.<project-ref>.supabase.co` требует доступного IPv6 (если не подключён
IPv4 add-on). Если локальная сеть без IPv6, выберите в Supabase Dashboard →
Connect режим **Session pooler** на порту `5432` и скопируйте выданные хост и
имя пользователя целиком. Режим Transaction pooler (`6543`) не подходит:
приложение использует блокировку PostgreSQL, привязанную к сеансу.

`--check` проверяет конфигурацию, подключение к PostgreSQL и способность
получить блокировку экземпляра, затем завершается. Обычный запуск остаётся
активным и корректно завершается по `SIGINT` или `SIGTERM`:

```bash
tg-jobs-searcher
```

Не добавляйте `.env`, файл Telethon-сессии или пароль из строки подключения в
Git.

## Тесты

Обычный запуск `pytest` выполняет модульные тесты. Интеграционные тесты
создают временную схему PostgreSQL, применяют к ней все миграции и удаляют
схему после проверки. Для них укажите отдельную тестовую базу и пользователя
с правом `CREATE SCHEMA`:

```bash
TEST_DATABASE_URL='postgresql+asyncpg://user:password@localhost:5432/test_db' \
  pytest tests/integration
```

Если `TEST_DATABASE_URL` не задан, эти тесты пропускаются. Рабочий
`DATABASE_URL` для них не используется.

## Telegram-авторизация и запуск

После заполнения `BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `TELEGRAM_API_ID`,
`TELEGRAM_API_HASH` и `TELEGRAM_SESSION_PATH`, подготовьте каталог для сессии
так, чтобы он принадлежал пользователю сервиса:

```bash
install -d -m 700 /var/lib/tg-jobs-searcher
tg-jobs-searcher auth
```

Команда запросит номер телефона, код из Telegram и пароль двухэтапной проверки,
если он включён. Она сохранит StringSession с правами `0600`; не копируйте её в
Git или сообщения. При обычном запуске приложение проверит сессию, подключит
бота. `OWNER_TELEGRAM_ID` — Telegram ID администратора; он один может
добавлять других пользователей:

```bash
tg-jobs-searcher
```

Базовые команды:

- `/start` — проверка подключения;
- `/help` — условия доступа к группам и каналам;
- `/available_groups` — список групп и каналов, доступных аккаунту (только администратор);
- `/check_group <ссылка, @username или ID>` — проверить, что аккаунт состоит в
  группе или каналу и может читать сообщения.

## Несколько пользователей

Кнопка «Меню» в личном чате Telegram показывает команды пользователя.
Администратор видит также команды управления. Тот же список доступен через
`/help`; команды с аргументами подскажут формат, если выбрать их в меню.

По умолчанию любой пользователь может открыть личный чат с ботом и сразу начать
работу через `/start`. Администратор может переключить режим входа командой
`/access_mode`: кнопки «Для всех» и «По приглашению». Настройка хранится в
PostgreSQL и сохраняется после перезапуска. В режиме приглашений новый
пользователь получает кнопку «Запросить инвайт»; администратор получает заявку
с кнопкой «Разрешить доступ». Переключение режима не меняет доступ уже
допущенных пользователей и не включает отключённых администратором.
При первом `/start` после открытия доступа бот сообщает администратору
(`OWNER_TELEGRAM_ID`, в текущей конфигурации `1466409`) имя, username и Telegram ID.
Группы, условия поиска, диалоги, задания сканирования и уведомления хранятся
отдельно для каждого Telegram ID.

Администратору доступны команды:

- `/add_user <Telegram ID>` — восстановить доступ отключённому пользователю;
- `/remove_user <Telegram ID>` — закрыть доступ конкретному пользователю;
- `/users` или `/list_users` — показать администратора, активных и отключённых пользователей.
- `/report_today` — получить статистику с сегодняшних 00:00 по GMT+3 до момента запроса.
- `/access_mode` — выбрать свободный вход или вход по приглашению.
- `/pause` — приостановить действия пользователей и отправку уведомлений;
- `/resume` — возобновить работу;
- `/pause_status` — проверить текущее состояние.

Пауза сохраняется в PostgreSQL и действует после перезапуска. Команда `/pause`
дожидается завершения уже начатых действий и отправок перед подтверждением.
Во время паузы пользователи не могут менять доступ или группы. Совпадения
продолжают сохраняться в очереди и отправляются после `/resume`.

Отключение администратором останавливает мониторинг и ожидающие уведомления,
но сохраняет настройки; повторное включение запускает восстановление последних
семи дней. Заявки на приглашение можно также одобрять через `/add_user <Telegram ID>`.

Пользователь может отправить `/feedback` и затем одним сообщением
описать идею, замечание или отзыв (до 3000 символов). Бот передаст текст
администратору вместе с Telegram ID и именем отправителя. Диалог можно отменить
через `/cancel`.

Бот отправляет администратору отчёт каждый день после 09:00 по времени Тбилиси
за предыдущий календарный день: сколько пользователей впервые отправили `/start`,
сколько уникальных пользователей заблокировали бота в Telegram, сколько чатов
добавили и удалили. Повторный `/start` не считается новым пользователем; повторное
добавление ранее удалённого чата считается добавлением. Если бот не работал во
время отправки, он догонит пропущенные дни после запуска. Простое удаление чата
без блокировки Telegram боту не сообщает, поэтому оно не входит в счётчик.

Группы и каналы читает **один общий Telethon-аккаунт**. При `/add` он попробует
вступить в группу или подписаться на канал по публичной ссылке, `@username`
или действующей пригласительной ссылке. По одному числовому ID вступить или
подписаться нельзя: нужна ссылка. Если требуется одобрение заявки, повторите
`/add` после него. Каждый пользователь может попросить общий аккаунт вступить
в группу или подписаться на канал; членства или подписки самого пользователя
недостаточно. Полный список групп и каналов этого аккаунта
через `/available_groups` доступен только администратору. Пользователи работают
с ботом только в личном чате.

## Управление группами

- `/add` запускает сохранённый диалог: ссылка или ID группы либо канала →
  выбор режима истории. Если общий список условий пуст, бот сначала попросит его заполнить;
- `/groups` открывает карточки добавленных групп и каналов;
- `/keywords` (пункт «Ключевые слова» в главном меню) открывает общий список условий поиска;
- `/status` показывает ход последних задач сканирования;
- `/cancel` отменяет незавершённый диалог.

У каждого пользователя один общий список условий поиска для всех его групп и каналов.
В разделе «Ключевые слова» можно добавлять, заменять и удалять условия: изменения сразу
применяются ко всем вашим чатам. Раздел работает и без добавленных групп. Новые и повторно добавленные чаты автоматически
используют этот список. Удаление последнего условия приостанавливает мониторинг
всех ваших чатов до добавления новых условий; группы с потерянным доступом
сохраняют свой статус. Удаление чата сохраняет общий список, даже если других чатов нет.
Обычно можно сохранить до 50 условий на пользователя.

Миграция `0010_shared_keywords` объединяет условия из всех неудалённых чатов
пользователя без дубликатов. Если суммарно их больше 50, они сохраняются целиком;
для добавления новых условий сначала сократите список. Условия поиска по общему
каталогу (`/search`) по-прежнему настраиваются отдельно.

В карточке также можно удалить чат из мониторинга. Удаление не выводит подключённый аккаунт из
самой Telegram-группы или канала. Незавершённые диалоги хранятся в PostgreSQL 30 минут и
переживают перезапуск приложения.

Каждая запись между запятыми — альтернативное условие (ИЛИ), а `&` связывает
обязательные фразы внутри условия (И). Например,
`frontend & #вакансия, vue 3 & react 21` найдёт пост с обеими фразами
`frontend` и `#вакансия` либо с обеими фразами `vue 3` и `react 21`.
Фразы с пробелами не требуют кавычек. Чтобы искать буквальный `&` или запятую,
заключите весь ключ в двойные кавычки: `"R&D" & developer` или
`"sales, marketing"`. Внутри кавычек двойная кавычка записывается дважды.
Каждое условие можно удалить целиком; старые сохранённые ключи остаются
отдельными буквальными условиями, даже если содержат `&`.

Чтобы отслеживать только одну тему группы, отправьте после `/add` публичную
ссылку на сообщение из этой темы, например `https://t.me/cyprusithr/46685`.
Бот проверит, что сообщение относится к доступной теме, и покажет её название
перед выбором режима истории. Обычная ссылка на группу включает всю группу,
а ссылка на канал — все его публикации. Для каждого чата сейчас можно добавить
один объект мониторинга: всю группу, одну её тему или канал.

В активной карточке доступна кнопка «Повторить поиск за 7 дней». Повторное
нажатие во время уже запущенного поиска показывает его существующий статус и
не создаёт второй такой же задачи. Если Telegram-аккаунт утратил доступ к
группе или каналу, карточка покажет кнопку проверки доступа.

## Уведомления, история и восстановление

После добавления группы или канала приложение начинает обрабатывать новые сообщения и
подписи к медиа. Для каждого сообщения используются условия поиска, которые
актуальны в PostgreSQL на момент его получения. Совпадение, включая список
выполненных условий, сохраняется вместе с уведомлением в транзакционной outbox
очереди. Поэтому повторное получение одного события не создаёт дубликат, а
временная ошибка Bot API будет повторена с задержкой. Уведомление содержит
источник, дату, выполненные условия, фрагмент текста и ссылку на сообщение, когда
Telegram может построить такую ссылку.
Если процесс остановится после успешной отправки, но до записи результата в
PostgreSQL, повторная попытка может доставить то же уведомление ещё раз.

При выборе режима истории после `/add` создаётся фоновая задача поиска за
последние 7 дней. Она читает историю страницами, сохраняет курсор и верхнюю
контрольную точку после каждой страницы. После перезапуска незавершённые задачи
возвращаются в очередь, а для активных групп запускается ограниченное семью
днями восстановление новых сообщений после последней контрольной точки.
Во время работы бот повторяет сверку каждые пять минут, чтобы найти сообщения,
обработка которых не удалась из-за временного сбоя. После ручного восстановления
доступа к группе сверка запускается сразу. Восстановление ограничено последними
семью днями.
Уже созданные задания истории сохраняют условия на момент постановки в очередь.
Новые задания, включая ручной повторный поиск, используют текущий общий список.
Совпадения истории и live-мониторинга используют один уникальный ключ в
PostgreSQL, поэтому уведомление для одного поста создаётся только один раз.

## Поиск по общему каталогу источников

Пользователь может отслеживать все источники, выбранные администратором, с одним
набором личных условий поиска. Этот режим работает параллельно с `/add` и `/groups`:

- `/search` — ввести или заменить условия; также можно сразу отправить
  `/search python & вакансия, frontend & remote`;
- `/search_status` — посмотреть условия, состояние поиска и число активных источников;
- `/search_stop` — остановить поиск по каталогу, сохранив условия;
- `/cancel` — отменить ввод условий.

Кнопки после `/start` позволяют выбрать поиск по всему каталогу или свои группы.
Синтаксис условий такой же, как для ваших групп. Условия индивидуальны для
каждого пользователя и начинают действовать с момента сохранения. Первоначальный
поиск старой истории по всем источникам не запускается. Ранее найденные и уже
поставленные в очередь сообщения могут прийти после изменения условий.

Каталог не включает автоматически все диалоги подключённого аккаунта: личные
переписки и другие чаты вне каталога не участвуют в общем поиске. Управление
каталогом доступно только администратору:

```text
/sources_add https://t.me/example_jobs
@another_jobs
https://t.me/+INVITE_LINK
```

Ссылки передаются по одной на строку. Список из 400 источников можно отправить
частями несколькими сообщениями с `/sources_add`. Допускаются публичные и
пригласительные ссылки, `@username`, а для уже доступных чатов — числовые ID.
Добавляется весь чат, без ограничения одной темой. Аккаунт приложения при
необходимости вступает в группу или подписывается на канал. Бот не требует
отдельной авторизации пользователей.

Ссылки сохраняются в очереди PostgreSQL. Один фоновый обработчик проверяет
источники последовательно, с паузой между попытками; `FloodWait` переносит
ожидающие попытки на время, указанное Telegram. Очередь переживает перезапуск.
Фиксированная пауза не гарантирует отсутствие ограничений Telegram. Для групп
с заявками на вступление после одобрения повторите `/sources_add` с той же ссылкой.

- `/sources [страница]` — общий каталог, ID, состояние и ошибки доступа;
- `/sources_status [страница ошибок]` — состояние очереди импорта и причины ошибок;
- `/sources_remove <ID>` — отключить источник в каталоге, оставаясь участником чата;
- `/sources_add <ссылка или ID>` — проверить доступ и включить источник заново.

Новые сообщения и подписи к медиа обрабатываются общим Telegram-клиентом.
Совпадения двух режимов, live-событий и восстановления имеют общий уникальный
ключ `(пользователь, чат, сообщение)`, поэтому создают одну запись уведомления.
Сохраняется оговорка о возможной повторной доставке при сбое между отправкой
в Telegram и подтверждением в PostgreSQL.

Каталог восстанавливает пропущенные сообщения страницами, один раз на источник
для всех пользователей. Курсор двигается только после сохранения всей страницы;
live-события его не меняют. После полной сверки следующая запланирована через
пять минут. При большом потоке обработка может занимать дольше. Восстановление
ограничено последними семью днями и временем включения источника и условий
пользователя. При потере доступа источник отключается и показывается в `/sources`;
для восстановления повторите `/sources_add`. Остановка общего поиска, отключение
источника или пользователя прекращают соответствующую отправку из очереди.
Если пост также подходит для активного поиска в личной группе, он может быть
доставлен по этому режиму. Общая `/pause` задерживает отправку уведомлений и
вступление в источники, но сохраняет новые совпадения.

Перед запуском обновлённого приложения примените миграции `alembic upgrade head`
(в том числе `0009_catalog_search`) и перезапустите процесс. Каталог изначально
пуст, действующие настройки поиска по личным группам сохраняются.
